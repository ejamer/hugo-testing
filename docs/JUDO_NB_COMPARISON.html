FENB × Judo NB

A comparison of fenb.ca (Fencing-Escrime NB) and judonb.org (Judo New Brunswick), with an effort-ranked list of ideas FENB can take from the comparison. Every recommendation is meant to stay on Hugo + GitHub Pages, cost nothing, and add little ongoing upkeep.

At a glance

Two good sites with opposite strengths

Judo NB's site is a polished custom web app built by a vendor. Its best parts explain a pathway: how to become a coach, how to become a referee, and how a child progresses through kata. It also profiles the provincial team. Several menu destinations are still stub pages, though, and it skips basic SEO plumbing. FENB's site is more complete and technically sounder, with search, RSS, an archived season schedule, results, and full bilingual policy pages. FENB's gaps are mostly in content: pathways shown visually, a Team NB roster, per-event actions such as calendar export, and a way to follow updates besides Facebook. There is also one real configuration bug (canonical host) worth fixing now.

Worth borrowing

What Judo NB does well

/en/nccp

A pathway you can locate yourself on

Four questions (age, belt, focus, current certification) produce a recommended starting stage, with a note to confirm with the PSO. FENB already has the pathway data in coach_pathways.yaml, so the same tool is a small piece of JavaScript.

/en/referees

The whole ladder on one screen

Provincial C → B → A, National C → B → A, Continental, International. Each rung lists what you can officiate, the minimum grade and the uniform. People can see where they are going before they start.

/en/kata

Evergreen learning content

A roadmap, a searchable glossary, and curated official videos. It is written once, rarely changes, gives families a reason to come back, and is good for search traffic.

/en/team

Faces of the provincial team

Grouped by age category, with weight class and home club. It shows that the clubs feed the provincial team, and it gives sponsors and families something to share.

/en/events/<slug>

Every event is actionable

Each event has a dedicated URL with "Register now", "Add to calendar (.ics)", "Share" and "Get directions". Parents want exactly these actions.

/en (homepage)

Task-first homepage copy

The headline is "Find judo in New Brunswick." with two buttons for the two most common tasks. The partner logo strip (Judo Canada, Sport NB, CSI Atlantic) adds credibility at no cost.

/en/support-team-nb

Low-effort fundraising

The PSO is a beneficiary of the Sport NB Gold Rush lottery, so the page only needs one outbound link. It earns money without anyone running an event.

/en/about/board

Role-based contact addresses

The site publishes president@ and executivedirector@ addresses instead of personal emails, so the site doesn't need an update when a role changes hands.

FENB technical findings

Issues found on the live site

Canonical host mismatch

GitHub Pages serves the site at https://www.fenb.ca/, and fenb.ca answers with a 301 redirect to www. The production baseURL is https://fenb.ca/, so every canonical tag, og:url, sitemap <loc>, hreflang link and absolute asset URL (favicon, lightbox.js) points at a URL that redirects. Search engines get mixed signals, and each absolute asset costs an extra round trip.

fenb-1/config/production/hugo.toml
- baseURL = "https://fenb.ca/"
+ baseURL = "https://www.fenb.ca/"
# …or switch the GitHub Pages custom domain to the apex instead. Pick one host and use it everywhere.
  • No robots.txt. /robots.txt returns the 404 page. Set enableRobotsTXT = true and add a layouts/robots.txt that names the sitemap.
  • No social share image. A Facebook share shows no picture. Add a default og:image (1200×630 with the bilingual logo) and let news articles override it with their own photo.
  • hreflang only in the sitemap. Also add <link rel="alternate" hreflang> per translation, plus x-default, in head-additions.html.
  • No skip link. Add a visually hidden "Skip to content" link before the nav (it's an accessibility basic Judo NB already has).
  • Thin descriptions. For example, Events is "2026–2027 season schedule". Write one task-led sentence per section page, in both languages.
  • No structured data. SportsOrganization JSON-LD on the homepage and SportsEvent per event, generated from events.yaml, can surface FENB events in Google's event listings.

Pitfalls to avoid

Lessons from Judo NB's weak spots

  • Stub pages in the menu. Results, Programs, Coaches & officials and Contact all say "This page is on the way". A missing link is better than a dead end. FENB's practice of tracking placeholders in TODO.md before release is worth keeping.
  • Fields you can't keep filled. Most Judo NB club pages show "Schedule: To be confirmed / Email: To be confirmed". Add a field to clubs.yaml only if someone will maintain it, and hide it when it's empty.
  • Vendor lock-in. A custom Next.js app is fast to look at but hard for volunteers to change. FENB's static YAML and Markdown approach is the right fit for a volunteer organization.
  • Linking other organizations' copies of documents. Judo NB's concussion protocol points to a 2018 PDF on judoalberta.com. Host your own copy or link to the national body's canonical URL.
  • Messy URLs and filenames. Event URLs containing spaces (/events/Fall camp- Camp d'automne 2026) and a policy file named julio-new-brunswick-safe-sport.pdf. FENB's slug conventions already prevent this.
  • Cards that don't go anywhere specific. Judo NB's homepage event cards all link to the generic events list. If FENB adds event pages, link each card to its own event.
  • Missing SEO basics. Judo NB has no sitemap, no robots.txt and no canonical tags. FENB is already ahead here, so don't regress.
Where FENB leads

Keep and protect these

  • Full-site bilingual search (Pagefind), including on the 404 page
  • Real news and results content, with RSS, instead of a Facebook redirect
  • Printable season schedule, past-season archive, and results linked from events
  • Policies as readable, searchable, bilingual HTML instead of PDFs
  • Join section for members, volunteers and new clubs; Hall of Fame
  • Programs beyond coaching and refereeing (armourer, secretariat)
  • Sitemap with hreflang, dark mode, light page weight, documented workflow and release process
Open questions

For future consideration

  • Is FENB eligible as a Support Your Sport NB Gold Rush beneficiary? It is a Sport NB program; ask Sport NB directly.
  • Does FENB control mail for fenb.ca? Role-based aliases (president@, info@) forwarded to current volunteers would make board and contact data almost maintenance-free.
  • Athlete consent. Before publishing a Team NB roster, agree on a consent rule for minors (name + club only, or photos with parental consent).
  • Revisit the Decap CMS plan (plans/non-technical-maintenance.md). New data-driven pages (team, glossary, event pages) are easier for non-developers if they land as YAML that a CMS can edit.
  • Watch Judo NB's stub pages (Results, Programs, Coaches). When they ship, they may be worth another look.
Implementation notes

For whoever acts on these recommendations

Approval and completion are tracked in docs/TODO.md under "Judo NB comparison". That is the source of truth, not the status menus above, which save only in one viewer's browser. Follow CLAUDE.md for branches, bilingual pairs, i18n and dark-mode rules.

Owner's constraints

From the site owner: every recommendation will be reviewed, but platform changes and paid services are unlikely to be adopted. The aim is to do more with what FENB already has, and the site must stay low-maintenance and low-cost. If an idea fits technically but adds recurring volunteer work, flag it instead of building it.

Needs a decision before building

  • R14 Team NB roster: needs an agreed consent rule for minors (name and club only, or photos with parental consent).
  • R19 Support FENB page: Sport NB must confirm FENB's eligibility as a Gold Rush beneficiary.
  • R21 Role-based contacts: depends on whether FENB controls mail forwarding for fenb.ca.
  • R18 Email updates: free-tier limits of RSS-to-email services were not checked; verify them before recommending one.

Checks before acting

  • R1 canonical host: the conclusion that the Pages custom domain is www.fenb.ca came from the live redirect (fenb.ca → 301 → www.fenb.ca), not from the repo's GitHub Pages settings. Confirm the custom domain first. Change baseURL and the Pages domain together; changing only one can break the site. config/development/hugo.toml is unaffected.
  • R9, R11, R20 event-driven features: build from partials/all-events.html, which merges events.yaml with data/events_archive/, not from events.yaml alone.
  • R6 partner strip: affiliations already appear on /about/organization/, read from hugo.Data.board_members.affiliations in layouts/about/organization/list.html. Don't start a second list. Move affiliations out of board_members.yaml into a new data/partners.yaml, since partners aren't board data, and have both the strip and the Organization sidebar read from it so the two never drift apart. Grep for board_members.affiliations before removing the old key.
  • R4 skip link: confirmed missing on the homepage only. Check baseof.html and the other layouts.
  • R3 share image: head-additions.html currently holds only the theme script. Check what Ananke's own head partials already emit before adding OG tags, to avoid duplicates.
  • Snapshot date: live-site findings date from 15 Oct 2026 (repo v0.5.18). Re-verify any finding before acting on it.

Method

How this was gathered

On 15 October 2026, judonb.org got one HEAD request, then robots.txt, sitemap.xml, the EN homepage, 15 top-level section pages, one French page, one event page and one club page. Requests were sequential, about 3 seconds apart, with no crawling of assets or JS bundles. fenb.ca got 4 requests: apex HEAD, homepage, robots.txt and sitemap.xml. Everything else about FENB comes from reading the hugo-testing repository; no files there were changed. Judo NB content may change after this date.
